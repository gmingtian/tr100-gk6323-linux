# TR100 pure-Linux p8 initrd contract

This separate candidate preserves all previous 800 MiB checkpoints and tooling. It only boots an already prepared pure-Linux root. It does not repartition, format, write a boot environment or reboot. Hardware actions and creation of the large root filesystem belong to the parent task.

The parent layout reserves the first 42 MiB for boot/hardware metadata and assigns the remaining 7,774,142,464 bytes (7414 MiB) to `/dev/mmcblk0p8`. This initrd requires the exact whole-disk size of 15,269,888 sectors, p8 start 86,016, p8 size 15,183,872, sysfs device `259:0`, and actual block-node hex device `103:0`. Only that fixed device may be mounted. Old p16 and loop-image identities are rejected. A kernel `root=` argument cannot redirect selection; every legacy `tr100.ramtest=*` argument, including `0`, and every `tr100.root_sha256=` argument fails closed because this candidate has no image-download mode. This matches the new-root bootstrap's accepted command-line set.

The fixed root UUID is `a8d4abf7-6ae4-4f9b-a39a-ef1b79c63230`; the image tag is `tr100-pure-linux-20261111`. Before mounting ext4 read/write at `/newroot`, read only the ext superblock magic (byte 1080) and UUID (byte 1128). Then require matching one-line `/etc/tr100/rootfs-uuid` and `/etc/tr100/image-tag` markers. BusyBox is static at the exact `/bin/busybox` basename; no dynamic blkid, network download, loop device or image copy is required.

Reuse the reviewed read-only new-root preflight: regular, non-symlink, executable `/usr/lib/tr100/busybox`, exact 1,284,688-byte ARM32LE identity and SHA256 `9b89dbebc390b4b9174a449df18b422892387bf35717a63cf1e0aef5b4e8dcfe`; real parent/API directories; exact bootstrap shebang and trusted initrd `sh -n`. Write three plain single-line handoff records `/run/tr100/{root-device,root-devnum,root-uuid}` with p8/259:0/new UUID, never source them. Move `/proc`, `/sys`, `/dev`, `/run` into the checked target directories, then execute `switch_root /newroot /usr/lib/tr100/busybox sh /usr/local/sbin/tr100-rom-bootstrap`. The new-root bootstrap independently verifies the same p8 contract.

PID 1 keeps a serial rescue-shell loop for failures before final exec. The old ash traps disappear at exec; internal BusyBox `switch_root`/`chroot`/NEW_INIT fatal failures can still end PID 1. Preflight removes the known missing/corrupt interpreter and invalid-script cases but does not claim recovery across that boundary. Windows fixtures cannot positively emulate Linux execute permission on an extensionless ARM ELF, so they exercise its real ELF/SHA checks and script checks separately; Linux `-x` and actual switching still require target verification.

The boot image preserves the factory kernel bytes. The new map places the kernel at p3 physical sector 16,384 (8 MiB), with a 24,576-sector (12 MiB) partition, while the boot loader reads `0x5000` sectors (10 MiB) from `0x4000`. The builder therefore retains the stricter `10,485,760`-byte image limit. It writes only a fresh output directory and records source/kernel/script/archive hashes. It never modifies the legacy ROM/full-CPIO artifacts.
