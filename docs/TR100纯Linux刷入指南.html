1　准备与文件校验

准备原电源、网线、沿用本次已验证接线和电平的 TTL 线。盒子使用独立电源，TTL 的 VCC 不用于给盒子供电。串口参数为 COM4、115200、8N1、无流控。脚本与 SuperCom 不得同时占用 COM4。

电脑使用 Windows PowerShell 7、Node.js 22.15 或更高版本、OpenSSH 客户端和可用的 System.IO.Ports。将 TR100-GK6323-Pure-Linux-20261111-final.zip 解压到例如 C:\TR100，使 boot.img、rootfs.ext4.gz、maintenance 等直接位于该目录。以下 Windows 命令均从解压目录运行。

电脑 PowerShell　只读校验
Set-Location 'C:\TR100'
New-Item -ItemType Directory -Path .\logs -Force | Out-Null
$ErrorActionPreference = 'Stop'
foreach ($line in Get-Content .\SHA256SUMS) {
    if ($line -notmatch '^([a-f0-9]{64})  (.+)$') { throw '清单格式错误' }
    $want = $Matches[1]; $file = $Matches[2]
    if ((Get-FileHash -LiteralPath $file -Algorithm SHA256).Hash.ToLowerInvariant() -ne $want) {
        throw "文件校验失败：$file"
    }
}
'PACKAGE_SHA256_OK'

本次网络为电脑有线地址 192.168.5.253/24，维护系统为 192.168.5.240/24，路由器为 192.168.5.1。确认 5.240 没有其他设备占用。加载脚本写死这组维护地址；地址不同须先核对并同步修改 loader、boot、服务监听与本文连接命令，不能只改一处。最终系统使用 DHCP，不固定为维护地址。

2　进入 fastboot

若当前 Linux 可以登录，先通过 SSH 执行 sync; systemctl reboot。在盒子启动早期通过 TTL 连续发送 Ctrl+C，直到看见 fastboot#。原厂 bootdelay 为 0，截停窗口很短；未截停成功就重新进行一次受控重启，不在 Linux 登录提示符下发送 bootloader 命令。原 Android 启动场景同样必须先取得 fastboot#。

已经在 fastboot# 时不要使用 saveenv、erase 或刷写 RAMONLY 镜像。关闭 SuperCom 的串口连接，释放 COM4，然后执行下一步。

3　启动内存维护系统

电脑窗口 A 启动 TFTP 服务，保持窗口运行。Windows 如需允许网络访问，仅允许此工具在当前可信局域网通信，不关闭整个防火墙。服务有效期为 10 分钟；超时后可在明确没有传输时重新启动。

电脑窗口 A
node .\maintenance\scripts\tftp-server.cjs 192.168.5.253 .\maintenance 192.168.5.240

电脑窗口 B 加载九片镜像并核验 CRC。日志文件名每次使用新的名字。只有出现 FULL_RAMONLY_IMAGE_LOADED_ALL_CRCS_MATCHED_NOT_BOOTED 才可继续。

电脑窗口 B　两条依次执行
pwsh -File .\maintenance\scripts\load-full-ramonly.ps1 -Manifest .\maintenance\RAMONLY-manifest.json -LogFile .\logs\ram-load-1.txt
pwsh -File .\maintenance\scripts\boot-pure-maintenance.ps1 -LogFile .\logs\ram-boot-1.txt

RAMONLY 九片只加载到内存，绝不能写到 eMMC。它们组合后约 143 MB，远大于持久 kernel 的读取窗口；包根目录约 9.86 MB 的 boot.img 才是本次持久启动镜像。

RAM 系统串口出现自动登录的 root shell 后再继续。启动脚本结束并释放 COM4 后，才可用 SuperCom 查看；不要向正在传输或启动中的盒子盲发 Ctrl+C。串口输入须使用约 15 ms 或更慢的逐字符发送，避免长命令丢字符。后续长脚本通过 SSH 文件传输，不直接快速粘贴到串口。

4　连接维护系统

RAM 系统地址为 192.168.5.240。它使用临时 SSH 主机密钥，只信任本次电脑已有的 SSH 公钥；最终系统的登录密码不能用于 RAM 维护系统。同一电脑保留原有 id_rsa 即可，不要复制、上传或公开 SSH 私钥。每次重新进入 RAM 系统都要重新核对其主机公钥。

盒子 TTL root shell　仅显示公钥指纹
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
电脑 PowerShell
ssh-keyscan -t ed25519 192.168.5.240 2>$null | Set-Content -Encoding ascii .\logs\ram-known_hosts
ssh-keygen -lf .\logs\ram-known_hosts
# 只有与 TTL 显示的指纹一致才继续
$sshArgs = @('-i', "$env:USERPROFILE/.ssh/id_rsa", '-o', 'HostKeyAlgorithms=ssh-ed25519', '-o', 'StrictHostKeyChecking=yes', '-o', 'UserKnownHostsFile=./logs/ram-known_hosts')
ssh @sshArgs root@192.168.5.240 'uname -r; findmnt -rn -o SOURCE,TARGET,MAJ:MIN; lsblk -b; cat /proc/swaps'

必须确认根为 RAM 的 rootfs、所有挂载的设备号为 0:*、没有任何 MMC 分区被挂载、没有 swap；eMMC 总大小为 7818182656 字节，新 p8 起始扇区为 86016、长度为 15183872 扇区。若不是此状态，停止，不执行写盘命令。

电脑 PowerShell　上传结束后冻结输入
ssh @sshArgs root@192.168.5.240 'test ! -L /run/tr100; mkdir -p /run/tr100/pure-flash'
scp @sshArgs .\boot.img .\bootargs.bin .\installation\probe-bootargs-NOT-FINAL.bin root@192.168.5.240:/run/tr100/pure-flash/
scp @sshArgs .\rootfs.ext4.gz root@192.168.5.240:/run/tr100/pure-flash/system.ext4.gz
scp @sshArgs .\scripts\flash-pure-from-ram.sh .\scripts\check-environment-from-ram.sh root@192.168.5.240:/run/tr100/pure-flash/

如果更换电脑而没有本次公钥登录权限，可使用 TTL 自动登录的 RAM root shell 与包内 tools/tcp-file.cjs 传输文件。该方式仍须核对接收文件长度及 SHA，不能把“传输完成”当作可刷入结论。具体 fixed-file 用法见包内 MAINTENANCE-RESOURCES.md。

5　切换临时引导环境

将附录的 probe-stage.sh 代码保存为 UTF-8 无 BOM、LF 换行的文件，放在电脑解压目录，然后上传运行。此脚本仅把 p2 改成“新分区图、bootcmd=printenv、bootdelay=3”，不写根和内核。必须得到 PROBE_ENV_FULL_READBACK_OK。它验证原引导和硬件参数摘要，拒绝其他设备；原厂环境、最终 Linux 环境或相同 probe 环境之外的 p2 都会被拒绝。

电脑 PowerShell　此步会写 p2
scp @sshArgs .\probe-stage.sh root@192.168.5.240:/run/tr100/pure-flash/probe-stage.sh
ssh @sshArgs root@192.168.5.240 'bash /run/tr100/pure-flash/probe-stage.sh'

第一次迁移需验证保存后的新图可经过完整 bootloader 启动：关闭 SuperCom，窗口 A 使用下面的被动捕获脚本；看到 READY 后，窗口 B 通过维护 SSH 重启。此时系统只自动 printenv 并停在 fastboot#，5.240 的 SSH 暂时断开是正常现象。

电脑窗口 A　被动监听
pwsh -File .\maintenance\scripts\capture-pure-map-probe.ps1 -LogFile .\logs\map-probe-boot.txt
电脑窗口 B
ssh @sshArgs root@192.168.5.240 'sync; /usr/lib/tr100/busybox reboot -f'

必须在新启动日志中看到 Bootrom、bootcmd=printenv、新八分区图、bootdelay=3 和 fastboot#。随后重复第 3、4 节，第二次加载 RAM 系统并重新核对 SSH 主机公钥、重新上传文件。重启会丢失 RAM 中所有文件；不能省略重新上传。数据写入期间一直保留 probe p2，不恢复原厂 bootcmd。

6　正式写入 Linux

在第二次 RAM 会话重新上传后，核对输入摘要。不要改动脚本内固定目标、摘要或容量限制。把附录两个环境脚本也重新上传，供后续使用。

电脑 PowerShell　只读检查
ssh @sshArgs root@192.168.5.240 'openssl dgst -sha256 /run/tr100/pure-flash/boot.img /run/tr100/pure-flash/system.ext4.gz /dev/mmcblk0p2'

boot.img 应为 c4e63e9a…22de7c9；system.ext4.gz 应为 d0dbbf2f…16baf942；p2 应为 216e4422…6b2db13f。完整值见第 10 节。可先以 --check 做只读预检；下面的 --write 自身也会重新执行全部预检，通过前不写块设备。

盒子 RAM bash shell　破坏性数据写入
# 以下在盒子 RAM 的 bash shell 中执行
set -o pipefail
/usr/lib/tr100/busybox sh /run/tr100/pure-flash/flash-pure-from-ram.sh --write --boot-sha256 c4e63e9a104d126685885b33db2c231f7ece5b5babc85f03531cc263722de7c9 --root-gzip-sha256 d0dbbf2fe3a97ac8874b0dc5346e4922f81b851ee9f5ce705749a77d16baf942 --root-raw-sha256 0a38283974f011256179a78b45edba6997dec51e16e90ec848265a67c42cdd46 2>&1 | tee /run/tr100/pure-flash/data-write.log

长命令可通过维护 SSH 发送，或将上述三行保存为 data-stage.sh 上传后执行 bash /run/tr100/pure-flash/data-stage.sh。在 PowerShell 中运行 scp 上传，不把 PowerShell 语法输入盒子 Linux。

脚本将从 42 MiB 到 eMMC 用户区末尾完整写入 Linux，完整读回根 SHA 后才清零整个 12 MiB 内核槽并写新 boot.img；随后核验内核、零尾和保护区。只认可 DATA_WRITE_COMPLETE 与相符的完整摘要，CHECK_PASSED 不是写入完成。操作期间保持电源、网线和 RAM 会话稳定，不重启。

任何 REFUSED、解压错误、摘要不一致、写盘或读回失败，都停留 RAM。不要继续提交最终环境，也不要恢复指向旧内核的原厂 bootcmd。probe 环境应保留。

7　提交最终引导环境

只有第 6 节完整写入及读回成功后，才把附录 final-stage.sh 保存并上传，运行 bash /run/tr100/pure-flash/final-stage.sh。它先检查本次 RAM 数据日志、p8 UUID、p3 内核摘要和当前 probe p2，再写最终 4 MiB 环境并完整读回。

电脑 PowerShell　此步会写最终 p2
scp @sshArgs .\final-stage.sh root@192.168.5.240:/run/tr100/pure-flash/final-stage.sh
ssh @sshArgs root@192.168.5.240 'bash /run/tr100/pure-flash/final-stage.sh'

成功必须包含 FINAL_ENV_COMMIT_AND_READBACK_COMPLETE；最终 p2 摘要为 06ea9291…f498885。之后不能再次把已经切为最终 p2 的系统当作 probe 状态运行数据脚本。

9　故障处理

现象处理
5.20 登录不上刷写时处于 RAM 维护系统，使用 5.240 和维护公钥；最终启动后查 DHCP 租约。
SSH 提示主机密钥变化重装与 RAM 重启会生成新密钥。先通过 TTL 核对指纹，仅更新对应 IP 的旧记录；不要关闭全部主机密钥检查。
TFTP 超时或 CRC 不符保持 fastboot，检查 PC 地址、UDP69、允许的 peer 和文件；重新加载成功前不 bootm，不写盘。
COM4 被占用释放 SuperCom 或其他脚本的串口连接，一次仅一个占用者。
REFUSED 或任何摘要/读回失败停止并保留 RAM 和日志，不能删校验条件绕过，也不能提交最终环境。
开机卡在 initrd 或 bootstrap通过 TTL 查看 STOPPED/FAILED 原因。保留实际状态，不自动格式化、猜分区或盲目重刷 bootloader。
HDMI 黑屏基础镜像需按第12节选装文字终端；本机已确认RGB565路径。服务启动前的早期内核日志仍在TTL。
大文件 wc 数值异常维护中仅用 /usr/bin/cat file | /usr/bin/wc -c 的真实管道计数；GNU9.1普通文件快捷路径和 BusyBox大计数均有本次发现的32位问题。

本包未实测独立 BootROM 救砖。原厂环境文件是受控恢复材料，不是数据写入期间的默认环境；用户数据、旧 Android private/securestore/userdata 不具备完整恢复备份。不要根据旧研究记录中被替代的“restore original p2”注释执行回退。

11　环境写入命令附录

下列代码是操作命令文本，打开文档不会执行。分别保存为 probe-stage.sh 和 final-stage.sh，使用 UTF-8 无 BOM、LF 换行，通过 SCP 上传后仅在已验证的 RAM 维护系统运行。初次原厂到 probe 的操作已实测；兼容最终 p2 再切 probe 的白名单用于本机重装，本文没有再进行第三次整机重刷。最终脚本沿用本次实际提交命令，并额外要求保存的数据完成日志。

probe-stage.sh　仅切换到安全 printenv 环境

h() { local v; v=$(openssl dgst -sha256 "$1"); printf '%s\n' "${v##* }"; }

awk '$3!~/^0:/ {bad=1} $5=="/" {ok=($3=="0:2")} END{exit(bad||!ok)}' /proc/self/mountinfo

test "$(cat /sys/class/block/mmcblk0/size)" = 15269888
test "$(cat /sys/class/block/mmcblk0p2/start)" = 8192
test "$(cat /sys/class/block/mmcblk0p2/size)" = 8192
test "$(cat /sys/class/block/mmcblk0p2/dev)" = 179:2
test "$(stat -c '%t:%T' /dev/mmcblk0p2)" = b3:2
test -b /dev/mmcblk0p2 && test ! -L /dev/mmcblk0p2
disk=$(readlink -f /sys/class/block/mmcblk0)

test "${part%/*}" = "$disk"
test "$(readlink -f /sys/dev/block/179:2)" = "$part"
test "$(h /dev/mmcblk0p1)" = fdc8847fafd9ef5ca006cb414561b99464b344deba1c16f8c223c0916f2c521e

test "$(h /dev/mmcblk0p5)" = 4ff6abeff404e8eeb0f0f3816470b3d65a9261c2ed75c6e4ce48fbf7fcc2f939
test "$(h /dev/mmcblk0p6)" = 9e56eb715425dd4e2f5e57f2211e4f69469104e3bbb1a473b666a463fa6a8237
test "$(h /dev/mmcblk0p7)" = b325063170911917d7511c37b1718ed815639c5aea08c47127e8d94487cd199a
f=/run/tr100/pure-flash/probe-bootargs-NOT-FINAL.bin

test "$(stat -c %s "$f")" = 4194304
test "$(h "$f")" = 216e44221aff6cf13f4cfeba8a2b97194a4a162220354a338b3fb8536b2db13f

case "$current" in
  489debc75ac9c3e525f5ecb336a18521e062b8ff6c10ff6551e3d4da6eabd2ac|06ea929120af9e164f5ad6f6845ecff0a720cf25515ce051e6b717a5ff498885|216e44221aff6cf13f4cfeba8a2b97194a4a162220354a338b3fb8536b2db13f) ;;

12　HDMI 文字终端选装

这项配置是基础刷机包之后增加的功能，不安装图形桌面。本机已确认 RGB565 文字可见、USB 键盘可以登录和输入命令。正式服务在一次受控软件重启后已自动启动并读回正确模式；物理断电启动没有另做验证。本文不把旧 ZIP 说成已经包含该配置。

从源码仓库下载 hdmi/ 目录并上传盒子，在源码根目录执行下列命令。完整说明和卸载回退命令见仓库 hdmi/README.md。新终端仍要求用户名和密码登录，串口 ttyAMA0 和 SSH 保留。

已启动的纯 Linux　root 执行，不在 RAM 维护系统安装
apt-get update
apt-get install fbset fbterm fonts-dejavu-core
install -o root -g root -m 0755 hdmi/bin/tr100-hdmi-console /usr/local/sbin/tr100-hdmi-console
install -o root -g root -m 0644 hdmi/systemd/tr100-hdmi-console.service /etc/systemd/system/tr100-hdmi-console.service
/usr/local/sbin/tr100-hdmi-console --check
systemctl mask getty@tty1.service
systemctl daemon-reload
systemctl enable --now tr100-hdmi-console.service
systemctl status tr100-hdmi-console.service --no-pager

终端固定为 fb0、1280×720、RGB565、24 像素 DejaVu Sans Mono，经 HDMI 的 1080p60 输出显示。厂商内核没有 fbcon，因此早期 BootROM 和内核启动文字仍只在 TTL；系统进入用户态后由 fbterm 显示本地登录。不要同时启动手工 fbterm、临时测试服务和正式服务。
